# 주석 작성 규칙

주석은 코드가 이미 보여주는 동작이 아니라 코드만으로 드러나지 않는 이유와 제약을
기록한다. 이름과 구조로 의도를 표현할 수 있다면 주석보다 코드를 먼저 개선한다.

## 기본 원칙

1. `WHAT`보다 `WHY`를 작성한다.
2. 코드와 같은 내용을 번역한 주석은 작성하지 않는다.
3. 주석은 한국어로 작성하되 코드 식별자와 외부 규격명은 원문을 유지한다.
4. 코드 변경 시 관련 주석도 함께 변경한다.
5. 주석 처리한 코드는 남기지 않고 Git 이력에서 확인한다.

ESLint와 coverage 지시문은 태그 규칙의 예외다. 지시문에 사유를 붙일 수 있다면
`--` 뒤에 비활성화 이유를 기록한다.

테스트 파일의 `@vitest-environment`, `TEST_LEVEL`, `PROVES`, `DOES_NOT_PROVE`는
실행 환경과 검증 범위를 명시하는 구조화 표식이므로 예외로 유지한다. 표식 이름은
원문을 유지하고 설명은 한국어로 작성한다.

## 태그

태그는 다음 네 가지만 대문자와 콜론을 포함한 형태로 사용한다.

- `TODO:` 구현할 작업과 완료 조건
- `FIXME:` 현재 확인된 결함과 수정 방향
- `NOTE:` 비직관적인 선택의 이유 또는 외부 제약
- `WARNING:` 변경 시 데이터 손실, 보안 문제 또는 호환성 파괴 가능성

```ts
// NOTE: OAuth callback이 앱 준비 전에 도착할 수 있어 argv를 먼저 보존한다.

// WARNING: 이 순서를 바꾸면 DB disconnect 전에 저장 작업이 끝나지 않을 수 있다.
```

## 문서화 주석

외부에서 호출하는 API 중 이름과 타입만으로 계약이 충분하지 않을 때만 TSDoc을
작성한다. 구현 순서를 설명하지 말고 역할, 입력·반환 계약, 예외와 부작용을 기록한다.
중첩 함수와 지역 구현에는 TSDoc을 사용하지 않는다.

```ts
/**
 * 종료 중인 background 작업을 멈추고 현재 실행을 모두 기다린다.
 *
 * @throws 작업을 안전하게 중단할 수 없는 경우
 */
export const pauseBackgroundWork = async (): Promise<void> => {};
```
