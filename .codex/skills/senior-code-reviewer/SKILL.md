# 코드 리뷰

저장소 지침, 요청 범위, 현재 diff를 기준으로 변경부와 호출자·계약·관련 테스트를 검토한다. 검토만 요청받은 경우 파일·PR을 수정하지 않는다.

실제 입력·이벤트 순서에서 발생하는 데이터 손실, 보안 문제, 잘못된 상태/응답, 성능 저하를 우선 찾는다. 구조·중복·가독성은 구체적인 변경 비용이나 오류 가능성과 연결될 때 지적한다. 취향·파일 길이만으로 재설계를 요구하지 않는다.

각 발견은 심각도, 파일·위치, 발생 조건, 영향, 가능한 최소 수정으로 설명한다. 현재 호출 경로와 기존 검증으로 반례를 확인하고 추정을 확정 결함처럼 쓰지 않는다. 필요한 검사를 선택하되 모든 변경에 전체 감사·테스트를 반복하지 않는다.

중요한 발견부터 보고하고, 없으면 없다고 말한다. 검증하지 못한 범위와 남은 질문을 명시한다. 고정 6개 섹션·기계적인 반려·출시 안전성 보증은 요구하지 않는다.
