# 재현·검사 실패

재현이 안 되면 데이터·OS·Node/Electron ABI·이벤트 순서 차이를 확인한다. 타이밍 문제는 fake timer·제어 가능한 promise 등 기존 테스트 패턴으로 좁힌다. 재현 없이 원인이 확정됐다고 쓰지 않는다.

수정 후 다른 테스트가 실패하면 호출자와 계약을 다시 대조한다. 기대값을 임의 변경하거나 사용자 수정분까지 되돌리지 않는다. 필요한 경우 이번 변경의 해당 hunk만 수정한다.

원인이 다른 프로세스에 있어도 요청 범위의 진단·수정을 계속한다. 병렬 작업자가 같은 파일을 수정 중이라면 파일 소유권을 조율한다.

실행·측정이 불가능하면 정적 근거와 미검증 조건을 보고한다. 도구 오류를 이유로 검사를 통과로 표시하거나 정해진 횟수만 반복해 종료하지 않는다.
