# 검토 도중의 제약

도구가 없으면 현재 가능한 소스·diff·테스트 검토를 수행하고 미실행 검사를 알린다. 추가 설치나 계정 연결을 기본 선행 조건으로 만들지 않는다.

의심되는 결함은 upstream 검증·호출 조건·기존 테스트로 반례를 확인한다. 근거가 부족하면 단순히 심각도를 낮춰 확정 결함으로 기록하지 말고 미확인 가설로 분리한다.

성능을 실행하지 못했으면 정적 위험으로 설명한다. 자료·시간·환경 제약으로 일부만 검토했으면 확인한 범위와 남은 범위를 구체적으로 보고한다.

외부 API·인증·한도 문제는 해당 검사를 멈추고 가능한 독립 작업을 계속한다. 리뷰 요청을 임의 수정·배포·메모리 쓰기 권한으로 확대하지 않는다.
